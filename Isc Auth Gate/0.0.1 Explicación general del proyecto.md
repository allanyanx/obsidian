### **1. Stack Tecnológico Principal**

- **Runtime**: **Bun** (tanto para servidor como para tests con `bun test` y scripts).
- **Framework**: **Next.js 16** (App Router) + **React 19** con React Compiler habilitado.
- **Autenticación**: **Better Auth (`1.7.1`)** con soporte multi-tenant, RBAC, MFA, Passkeys, OAuth 2.1 Server y Microsoft Entra ID.
- **Base de Datos**: **PostgreSQL** gestionado con **Drizzle ORM** (`database/schema.ts`). En tests usa **SQLite en memoria** (`tests/database.ts` y `database/schema-sqlite.ts`).
- **UI & Estilos**: **Tailwind CSS 4** + **shadcn/ui** (preset `base-nova` con `@base-ui/react`).
- **Emails**: **React Email** + Nodemailer SMTP.
- **Estado en cliente**: **SWR** (fetching/caché de datos del servidor) y **Jotai** (átomos de estado local).

### **2. Funcionalidades Clave**

1. **Servidor OAuth 2.1 / OIDC y Device Flow**: Permite que aplicaciones internas o de terceros deleguen su autenticación en este servidor (clientes OAuth administrables desde `/dashboard/administration/oauth`, soporte de PKCE, JWKS, consentimiento y autorización de dispositivos CLI). Ejemplos de clientes de prueba en `examples/oauth-test-client/` y `examples/device-cli/`.
2. **Múltiples Métodos de Inicio de Sesión**:
    - Correo y contraseña (con registro público deshabilitado por seguridad: `disableSignUp: true`).
    - SSO corporativo con **Microsoft Entra ID** (opcional, se activa automáticamente si están configuradas las variables de entorno).
    - **Passkeys (WebAuthn)**, **Magic Link**, **Email OTP**, **2FA (TOTP/OTP)** y **API Keys**.
3. **Multi-Tenancy y Control de Acceso (RBAC + DAC)**:
    - Definido en `lib/permissions.ts` mediante `accessControl`.
    - Roles globales (`admin`, `moderator`, `user`) y roles por organización (`owner`, `admin`, `member`, `systemAdmin`), además de creación dinámica de roles por organización (DAC).
4. **Flujo de Primer Arranque (`/setup`)**:
    - `needsSetup()` verifica si existe al menos un usuario con rol `admin`.
    - Si la base de datos está recién migrada y sin administrador, redirige a `/setup`, donde `completeSetup()` crea el primer admin y la organización inicial dentro de una única transacción protegida con `pg_advisory_xact_lock`.
