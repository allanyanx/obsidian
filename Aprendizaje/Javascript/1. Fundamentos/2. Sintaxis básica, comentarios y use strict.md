## Sintaxis básica

**Sentencias y punto y coma**  
Un programa es una secuencia de sentencias. El `;` es opcional gracias a la _inserción automática de punto y coma_ (ASI), pero se recomienda usarlo para evitar errores sutiles.

```js
let a = 5;
let b = 10
console.log(a + b);
```

**Sensibilidad a mayúsculas**  
`nombre`, `Nombre` y `NOMBRE` son identificadores distintos.

**Identificadores (nombres de variables/funciones)**

- Pueden contener letras, dígitos, `_` y `$`.
- No pueden empezar con dígito.
- No pueden ser palabras reservadas (`class`, `if`, `return`, etc.).
- Convención: `camelCase` para variables y funciones, `PascalCase` para clases, `MAYUSCULAS_CON_GUION` para constantes globales.

```js
let nombreUsuario = "Ana";
const MAX_INTENTOS = 3;
class CuentaBancaria {}
```

**Declaración de variables**

```js
let x = 1;      // reasignable, ámbito de bloque
const y = 2;    // no reasignable, ámbito de bloque
var z = 3;      // antiguo, ámbito de función (evitar)
```

**Bloques y llaves**  
Se agrupan sentencias con `{ }`.

```js
if (x > 0) {
  console.log("positivo");
}
```

**Tipos básicos**  
`string`, `number`, `bigint`, `boolean`, `undefined`, `null`, `symbol` y `object`.

**Espacios y saltos de línea**  
Se ignoran en su mayoría; sirven para legibilidad.

**Salida básica**

```js
console.log("Hola, mundo");
```

## Comentarios

```js
// Comentario de una línea

/* Comentario
   de varias líneas */

/**
 * Comentario de documentación (JSDoc)
 * @param {number} a
 * @returns {number}
 */
function doble(a) {
  return a * 2; // comentario al final de línea
}
```

- No se pueden anidar los comentarios `/* */`.
- Útil: comentar código para desactivarlo temporalmente.
- Hashbang (`#!/usr/bin/env node`) en la primera línea de scripts de Node es válido desde ES2023.

## `"use strict"` (modo estricto)

Introducido en ES5. Es una directiva que activa una variante más segura del lenguaje: convierte errores silenciosos en excepciones y prohíbe construcciones problemáticas.

**Cómo activarlo**

```js
"use strict";            // a nivel de archivo/script (debe ser la primera sentencia)

function f() {
  "use strict";          // solo dentro de esta función
}
```

**Qué cambia**

```js
"use strict";

x = 10;                          // ReferenceError: variable no declarada
delete Object.prototype;         // TypeError
function g(a, a) {}              // SyntaxError: parámetros duplicados
let obj = { get v() { return 1; } };
obj.v = 2;                       // TypeError: propiedad solo de lectura
const o = Object.freeze({ a: 1 });
o.a = 2;                         // TypeError (sin strict falla en silencio)

function h() { return this; }
h();                             // undefined (sin strict sería window/globalThis)
```

También prohíbe octales heredados (`010`), la sentencia `with`, y reserva palabras como `let`, `static`, `implements`, `interface`, `package`, `private`, `protected`, `public`.

**Cuándo ya no hace falta escribirlo**  
Es **automático** en:

- **Módulos ES** (`import`/`export`, `<script type="module">`).
- **Clases** (el cuerpo de una `class`).

En scripts clásicos (y CommonJS en Node) sí debes declararlo explícitamente.

**Advertencia:** la directiva debe ser la primera sentencia; si va después de otro código, se ignora. Y concatenar un script estricto con uno no estricto puede cambiar el comportamiento del segundo.

## Resumen

|Tema|Clave|
|---|---|
|`;`|Opcional por ASI, pero recomendable|
|Variables|Usa `const` por defecto, `let` si reasignas, evita `var`|
|Comentarios|`//`, `/* */`, `/** */` (JSDoc)|
|`"use strict"`|Errores más claros y código más seguro; automático en módulos y clases|
